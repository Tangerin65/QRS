# 档案管理系统微信小程序

成员 3 的公共前端，版本 0.3.0。原生微信小程序，导入本目录即可查看。当前尚未接入真实后端。

已实现公共首页、按服务端权限显示的菜单、公共请求/错误/重试、微信免登接入、退出/切换账号、扫码绑定、电脑扫码登录的核验与确认/拒绝页面。查档、消息和个人资料业务由对应模块后续接入，当前页面明确显示未开放。

界面采用分组工作台和彩色图标，首页提供应用入口与可展开的使用指南，账号服务使用列表布局。图标为本项目绘制的本地 PNG；参考页面的布局，没有引入第三方模板代码或图片。公共状态、扫一扫和业务未开放页面使用同一套样式。

## 查看

1. 首次拉取后，将 project.config.example.json 复制为 project.config.json，填入团队确认的 AppID；已有本地配置可继续使用。
2. 微信开发者工具导入本目录。project.config.json 和 project.private.config.json 仅在本机保留，不提交 Git。
3. baseUrl 留空可查看公共页面。此时没有真实登录，不显示业务权限菜单。
4. 在 config/index.js 配置已部署的 HTTPS 地址，按团队实际接口协议调整路径及权限名。
5. 与成员 6 提供的账号、绑定和扫码登录后端联调。接口是待确认契约，不能只填地址就视为流程验收完成。

详细接口字段、分工、安全边界与测试步骤见 [接入说明](../doc/team/小程序公共部分接入说明.md)。

## 开发约定

- utils/session.js 管理登录状态；凭证只在内存中保存，不放入 Page.data、日志或本地存储。
- utils/navigation.js 统一控制菜单、底部导航和入口权限；角色名称本身不授予权限。
- utils/request.js 统一 JSON、HTTPS、Token 和中文错误；Promise 成功返回 data。
- utils/qr.js 区分纯用户编号和电脑随机登录票据。
- 微信 AppSecret 和 OpenID 兑换只在服务端处理。
- 主动退出不会解除平台绑定。换绑需管理员解除原绑定后重新扫码。
- 同一请求提交期间禁止重复点击；错误重试不自动重复发送写入操作。
- 不提交开发工具私有配置或编译产物。
- 后端仍需逐次校验角色、部门、密级与账号状态。

## 测试

在仓库根目录执行：

~~~powershell
node --test tests/mini-program.test.cjs
~~~

脚本使用微信 API 替身检查前端逻辑；不能代替真实微信、后端、真机和性能验收。
